# Pyright を環境変数（PYRIGHT_PYTHON）と CLI で揃える（2026-04-11）

## 変更内容

| 対象 | 内容 |
|------|------|
| `backend/pyproject.toml` | マシン固有だった `venvPath` / `venv` を削除。Pyright は設定ファイル内で `$VAR` 展開をしないため、共有設定に絶対パスを載せない方針に変更。 |
| `backend/scripts/run-pyright.sh` | `PYRIGHT_PYTHON` があればそれを、なければ `python3.13` または `python` を `pyright --pythonpath` に渡すラッパー。 |
| `backend/.env.example` | 任意の `PYRIGHT_PYTHON` を追記（開発用）。 |
| `backend/README.md` | 検証コマンドと「本番では不要」の説明を追記。 |

## 本番デプロイ先にこの変数は要るか

**不要。** Pyright は開発・CI 用の静的型チェックであり、本番コンテナの起動（例: `uvicorn`）には使わない。Railway 等の環境変数に `PYRIGHT_PYTHON` を設定する必要はない。

## 補足（なぜこの形か）

- 公式ドキュメントでも、他開発者とパスがずれる `venvPath` は共有設定に書かず、**CLI やユーザー別設定**に回すことが推奨されている。
- `--pythonpath` はそのインタプリタの `sys.path` を使うため、conda の `py313` でも `.venv` でも同じやり方で揃えられる。
