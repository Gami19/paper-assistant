# ADR-004: F4-3（運用コスト管理）を第 1 段階と第 2 段階に分ける

## Status

Accepted

## Context

- [運用コスト.md](../運用コスト.md) のとおり、**完全な一元ダッシュボードは各社に存在しない**。
- 各プロバイダ（AWS / Vercel / Railway / Supabase）の **自動取得は API・権限・仕様変更**のコストが高い。

## Decision

F4-3 は次の **2 段階**で実装する。

1. **第 1 段階（必須・先に実装）**: サービス別カード、**公式 Billing へのリンク**、**月次の手入力**、画面上の**合計**、**永続化**（[実装計画.md](../実装計画.md) §6.1）。
2. **第 2 段階（任意）**: プロバイダ別の **自動取得**。失敗時は **第 1 段階の手入力にフォールバック**（§6.2）。

第 2 段階の実装場所は [ADR-002](./ADR-002-cost-api-nextjs-route-handler.md) に従い、**Next.js サーバ側（Route Handler / server-only モジュール）**とする。

## Consequences

### ポジティブ

- **すぐ運用記録が始められる**（月次のリズムと整合）。
- 自動取得の遅延・失敗があっても **手入力で穴埋め**できる。

### ネガティブ

- 第 1 段階では **人間の入力ミス**に依存する。注記・為替レートの明示で **透明性**を補う。

## Alternatives

| 案 | 却下理由 |
|----|----------|
| **最初から全プロバイダ自動取得のみ** | 権限設計と実装が重く、**MVP を遅らせる**。 |
| **手入力のみで第 2 段階を永久にやらない** | 許容されるが、**ADR の再評価**で明示的に決めればよい。 |

## Compliance

- 第 2 段階を開始する際、**どのプロバイダから着手するか**を短いメモまたは子 ADR で残す。
- UI には **「自動値と手入力のどちらか」**が分かる表示を推奨（運用コストの信頼性）。
