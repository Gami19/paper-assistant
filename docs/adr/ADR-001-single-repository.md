# ADR-001: 単一リポジトリ（`frontend/` / `backend/`）

## Status

Accepted

## Context

- プロジェクトは **個人検証・非商用**（[実装計画.md](../実装計画.md) §1）で、Next.js（Vercel）と FastAPI（Railway）の **2 デプロイ**を前提とする。
- リポジトリを **frontend / backend で分割**する選択肢もあるが、チーム規模とリリースサイクルでは **オーバーヘッドが大きい**。

## Decision

**単一リポジトリ**とし、ルート直下に **`frontend/`** と **`backend/`** を置く。モジュール境界は **ディレクトリと import 規律**で表現し、現時点では **別リポジトリに分割しない**。

## Consequences

### ポジティブ

- 仕様・型・小さな共有物を **同一 PR / 同一履歴**で追いやすい。
- ローカルで **フロントと API を同じクローン**から起動しやすい。
- CI で **両方の品質ゲート**をまとめて掛けられる。

### ネガティブ

- リポジトリの **アクセス権限をフロントだけ公開**するなどの分離はしにくい（将来分割時にコストが発生する）。
- 変更が **両ディレクトリにまたがる**と PR が大きくなりうる。

## Alternatives

| 案 | 却下理由 |
|----|----------|
| **frontend / backend を別リポジトリ** | 個人検証では **連携・バージョン追跡のコスト**がメリットを上回る。 |
| **モノレポツール必須（Nx 等）** | 現規模では **素のディレクトリ分割**で足りる。必要になったら再検討。 |

## Compliance

- 新規コードは **`frontend/` または `backend/` 配下**に置く。ルートにアプリ本体を増やす場合は ADR または実装計画の更新で理由を残す。
